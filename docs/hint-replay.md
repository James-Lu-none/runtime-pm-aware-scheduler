
# Limited application hints: randomized replay

The original periodic V2 test has a deterministic workload cycle. This
experiment changes task order while holding the 500 ms arrival period,
model counts, deadlines, input sequence and telemetry protocol fixed.
Every repetition generates one balanced shuffled trace; all policies
in that repetition replay it. The seed and SHA256 are recorded, and
notice tokens are generated by an independent seeded PRNG.

```sh
cmake --build build -j4
ctest --test-dir build --output-on-failure
python3 tests/test_hint_replay.py
sudo python3 scripts/benchmark_cpu_dvfs.py --jobs 60 --repeats 1 \
  --hint-sweep 0 25 150 --hint-mixed-ms 150 --hint-static-ms 25
```

For a full lead-time sweep:
```sh
sudo python3 scripts/benchmark_cpu_dvfs.py --jobs 300 --repeats 3 \
  --hint-sweep 0 10 25 50 100 150 --hint-mixed-ms 150 --hint-static-ms 25
```

Arms: original native governor, V2 lookahead (oracle knows the next job
immediately after prior completion; upscale lead defaults to 150 ms),
hint_fixed_N (job model/deadline/release revealed N ms before release),
hint_mixed_N (per-job notice uniformly sampled approximately 0..N ms),
and optional hint_static_N (same notice as fixed N, but the per-class
minimum-energy feasible frequency is selected without transition cost,
remaining-time adaptation, or hysteresis). Static is a simple mapping
baseline, not a globally optimal offline schedule. Compare static and
dynamic at the same N. Zero notice uses the same hint path at release,
not the exact old V1 frame-preparation order.

The hint path waits for the notification before passing the job's
model/deadline into the selector. It calculates remaining slack and
actual available lead and immediately attempts a chosen switch; dwell
and savings hysteresis are evaluated at decision time, while deadline
feasibility can override them. The oracle has a different action timing
policy (early downscale, scheduled upscale), so oracle vs fixed lead
also differs in scheduling policy; the fixed-lead sweep is the controlled
comparison. The replay is an in-process simulation, not an asynchronous
IPC producer or security isolation boundary. The selector gets no future
jobs, but the replay harness necessarily holds the full trace. Single
serial worker: late completion can delay observing the next hint;
there is no concurrent hint queue, arrival jitter, or mispredicted
release/deadline. No inference runs before release. The trace validation
checks exact workload identity, notification timestamps, and that no
hint-triggered switch starts before notification. Actual lead may be
shorter than requested due to OS scheduling.

The low-observer multi-rate defaults are now 500/137/500/1000 ms for
frequency/PMIC/temperature/CPUIdle respectively, with kernel trace enabled.
All arms use the same settings. Thermal supervisor experiments are
separate. Existing V1/V2 modes and old cyclic workload remain available.
Energy scores use the previous period-specific profiles; measured rail
energy remains approximate. Compare deadline miss rate, normalized
latency, on-path switching, goodput and energy per on-time job. Do not
claim prediction accuracy or generic governor superiority from this test.
